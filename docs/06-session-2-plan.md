## 1. 예약 요청 (그대로 적을 내용)

| 항목 | 값 |
|---|---|
| **필요 시간** | **3시간** (측정 2시간 + 여유 1시간) |
| **필요 NPU** | **RNGD 8장 전부** (`npu:0` ~ `npu:7`) |
| **독점 여부** | **필수** — 다른 프로세스가 NPU를 쓰면 측정이 무효가 됩니다 |
| **호스트** | `edu-hlu-1` |

### 사용할 모델

| 모델 | 필요 카드 | 용도 |
|---|---:|---|
| `furiosa-ai/Qwen3-8B-FP8` | **1장** | 주 측정 대상 (세션 1과 동일) |
| `furiosa-ai/Qwen3-8B-FP8` | **8장** | 카드 확장 효율 재측정 |
| `furiosa-ai/Qwen3-Embedding-0.6B` | **1장** | 임베딩 처리량 |
| `furiosa-ai/Qwen3-32B-FP8` | **4장** | 모델 비교 |
| `furiosa-ai/Qwen2.5-0.5B-Instruct` | 1장 | 스모크 (선택) |

> ⚠️ **`Qwen3-32B-FP8`은 카드 1장에 올라가지 않습니다.**
> 아티팩트가 `tensor_parallel_size=32`, `devices=['npu:0:0-7, npu:1:0-7, npu:2:0-7, npu:3:0-7']`
> 로 빌드돼 있습니다. **4장이 최소 단위**입니다. 이것 자체가 모델 선택 가이드의 결과입니다 —
> 32B는 "카드당 용량"을 8B와 같은 방식으로 비교할 수 없습니다.

### 왜 8장이 다 필요한가

측정 대부분은 1장으로 합니다. 8장이 필요한 이유는 두 가지입니다.

1. **카드 확장 효율 재측정** — 세션 1의 8장·카드당 동시성 32 결과(82.1%)가 비교군 중
   측정창이 가장 짧습니다(14.6초). 측정창이 결과를 45%까지 바꾼 전례가 있어 확인이 필요합니다.
2. **32B가 4장을 요구** — 위 참조.

그리고 **독점이 카드 수보다 중요합니다.** 세션 1에서 두 측정을 동시에 돌렸다가
처리량이 26% 떨어졌습니다(707 → 521 tok/s). 1장짜리 측정이라도 머신 전체가 조용해야 합니다.

## 2. 실행 계획

서버 설정을 바꾸려면 재기동해야 하므로 **설정 하나에서 가능한 것을 전부 끝내고** 넘어갑니다.
모델 로드는 25초입니다(세션 1 실측).

### 구간 A — 8B / 1장 (`npu:0`) · 55분

| 순서 | 실험 | 목적 | 예상 |
|---|---|---|---|
| A-1 | **B1 고동시성 단독 재측정** | conc 64/128/256의 현재 근거가 다른 측정과 **동시 실행**된 것. 치트시트에 들어가는 숫자다 | 5분 |
| A-2 | **긴 입력 고동시성** | in=1024/2048은 conc≤32까지만 긴 창으로 쟀다. **긴 입력에서 절벽이 어디인지 모른다** | 10분 |
| A-3 | **B7 폴링 용량-반응** | soak 처리량 도약(475→687)의 기전 확정. 폴러 0/1/2개 × 각 3분 | 10분 |
| A-4 | **B2 KV 캐시 포화점** | 카드당 상한 263,329 토큰의 실제 한계. 어디서 대기열이 생기는가 | 10분 |
| A-5 | **B3 혼합 부하 간섭** | 실무 가치 최고. 긴 문서가 들어올 때 다른 사용자가 얼마나 느려지는가 | 15분 |
| | 기동·여유 | | 5분 |

### 구간 B — 8B / 8장 (`npu:0-7`) · 10분

카드당 동시성 32에서 측정창 60초 이상으로 재측정. 82.1%가 실제인지 짧은 창 아티팩트인지 확정.

### 구간 C — Embedding / 1장 (`npu:0`) · 20분

`Qwen3-Embedding-0.6B`. batch 1~64 × 문서 길이 2종. 단위는 **documents/s**.

### 구간 D — 32B / 4장 (`npu:0-3`) · 30분

프론티어 부분집합(conc 1/4/16/32/64) + prefill 계단 축약 스캔.
카드 4장이 최소 단위이므로 "4장 묶음당 용량"으로 기록합니다.

## 3. 시간이 부족할 때 자르는 순서

**자르는 순서**: D(32B) → C(임베딩) → B(8장 재측정) → A-4(KV 포화)

**절대 자르지 않는 것**
- **A-1** — 치트시트 숫자의 근거가 오염된 상태다
- **A-3** — 기전 미확인 항목을 문서에 남겨둔 채로 둘 수 없다
- **A-5** — 러너까지 만들어놨고 실무 가치가 가장 높다
